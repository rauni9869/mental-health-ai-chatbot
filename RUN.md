# How to run Steady

Steady uses **open-weight models only**. There is no OpenAI key. I cannot put a Groq/OpenAI secret in the repo — that would leak into git. Local Ollama needs **no LLM API key**.

You still need:

- `AUTH_SECRET` — random string for login cookies (generated by the setup script)
- `POSTGRES_URL` — local Postgres (started by Docker Compose)
- Ollama running with `llama3.1` pulled

## 0. Prerequisites

- Node 18+ and [pnpm](https://pnpm.io/installation): `npm install -g pnpm`
- [Docker Desktop](https://www.docker.com/products/docker-desktop/) (Postgres, optional Ollama)
- [Ollama](https://ollama.com/download) on your machine (recommended) **or** the `ollama` service in `docker-compose.yml`

## 1. Clone and install

```bash
git clone https://github.com/rauni9869/mental-health-ai-chatbot.git
cd mental-health-ai-chatbot
git checkout cursor/steady-wellness-assistant-c31f   # or main after merge
chmod +x scripts/setup-local.sh
pnpm setup:local
```

`pnpm setup:local` will:

1. Create **gitignored** `.env.local` with a generated `AUTH_SECRET`, local Postgres URL, and `OLLAMA_BASE_URL=http://127.0.0.1:11434`
2. Start Postgres with Docker Compose
3. `pnpm install` and run migrations

## 2. Pull the open-source model (once)

Native Ollama (easiest):

```bash
ollama serve          # if it is not already running
ollama pull llama3.1
```

Or Docker:

```bash
docker compose up -d ollama
docker compose exec ollama ollama pull llama3.1
```

`llama3.1` is several GB. Wait until the pull finishes.

## 3. Start the site

```bash
pnpm dev
```

Then:

| URL | What you get |
| --- | --- |
| http://localhost:3000 | Public product site |
| http://localhost:3000/app | Companion chat (creates a guest session) |
| http://localhost:3000/breathe | Box-breathing timer |
| http://localhost:3000/check-ins | Mood log |
| http://localhost:3000/skills | Coping skills |
| http://localhost:3000/register | Optional account |

## 4. Check that it works

```bash
pnpm test:unit
```

In `/app`, send something like: “I feel a panic wave, help me ride it out.” You should get a skill walkthrough, not a web search.

Imminent-harm language should skip the model and show crisis resources (988 in the US).

## Optional: Groq instead of local Ollama

Groq hosts **open-weight** Llama, not GPT. It is optional and faster if you do not want to run a local GPU/CPU model.

1. Create a free key at https://console.groq.com/keys
2. Add **only to `.env.local`** (never commit it):

```bash
GROQ_API_KEY=gsk_your_key_here
# remove or comment OLLAMA_BASE_URL so Groq is used
```

Restart `pnpm dev`.

There is still **no OpenAI key**.

## Common failures

| Symptom | Fix |
| --- | --- |
| `POSTGRES_URL is not defined` | Run `pnpm setup:local` or copy `.env.example` → `.env.local` |
| Chat errors / connection refused on 11434 | `ollama serve` and `ollama pull llama3.1` |
| Guest loop / login broken | `AUTH_SECRET` missing in `.env.local` |
| Port 5432 in use | Stop local Postgres or change the compose port |
| Port 3000 in use | `pnpm dev -- --port 3001` |

## What not to do

- Do not add `OPENAI_API_KEY`
- Do not commit `.env.local`
- Do not treat this as therapy or a crisis line
